What is this?

Pick a spot on the Moon's south pole. Using real NASA data, the tool shows when it has sunlight (power) and when it can talk to Earth, and whether a mission would survive there. The default site is where MoonDAO plans to build a lunar base.

for a mission planner
Compare Artemis III candidate sites on the numbers that pick a landing spot: longest darkness (battery), Earth-contact uptime and longest blackout (comms autonomy), and ground slope (landability). All from real JPL Horizons + LOLA terrain.
for a command operator
Sign a command on the Seeker with a post-quantum signature. The asset executes only if the signature verifies, the counter is fresh (anti-replay), and it is inside a real comm window. A forged, replayed, or out-of-window command is rejected.

why post-quantum

the map doesn't need crypto. the command does. a forged command to a lunar asset is not a data leak, it is takeover: point the antenna off-Earth, drain the battery, brick the lander. a classical signature (ed25519) rests on math a future quantum computer breaks, and the asset lives for decades on a key you cannot rotate once it is on the Moon. so the signing authority must be quantum-resistant from launch. this is a longevity and forgery argument, not "harvest now, decrypt later" (that is about encryption, not signatures). every command is signed hybrid: ed25519 (classical, Seed Vault identity) and ML-DSA (FIPS 204, post-quantum, keystore). if either scheme holds, the command is still authentic.
cost is real: an ML-DSA-65 signature is kilobytes against tens of bytes for ed25519, on a starved telecommand link. justified for long-lived, high-value, hard-to-rekey assets, which is exactly this one. ESA's E2EQSS proposes this same ML-DSA-65 + ML-KEM-768 direction for CCSDS/SDLS; it is not yet a ratified standard.
